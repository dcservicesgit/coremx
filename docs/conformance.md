# ActiveSync implementation and acceptance matrix

CoreMX advertises **14.1, 16.0 and 16.1** when `coremx.experimentalActiveSync` is enabled. It remains disabled by default. This matrix describes implemented behavior and automated verification; it is not a claim of Microsoft certification or physical-device interoperability.

| Capability | Implemented behavior |
| --- | --- |
| Transport and WBXML | CentralFW ingress, plain and packed/base64 queries, version gates, bounded decoding, command/root validation, structured errors, cancellation, multipart responses, bounded in-flight requests. |
| Autodiscover | Authenticated MobileSync XML discovery for the mailbox and configured public origin. |
| Folder hierarchy | Initial/incremental FolderSync, custom email/calendar/contact/task/note folders, atomic CRUD/retry responses and cycle prevention. Drafts appear for 16.x devices. |
| Email Sync | Incremental changes, conflicts, read/flag/categories, deletion/moves, pagination, filter windows, SoftDelete, Fetch, GetChanges, saved empty requests, Partial collections, Wait/HeartbeatInterval and conversation filtering. Mutation, quota, snapshot and replay response commit together. |
| Bodies and attachments | Plain/HTML/MIME preferences, MIME truncation, UTF-8-safe truncation, previews, HTML body parts, inline/base64 or multipart fetch, byte ranges, schema selection, mailbox ownership checks and policy limits. |
| SendMail / SmartReply / SmartForward | Durable submission deduplication, source lookup by folder/item or LongId, MIME replacement, quoted plain/HTML replies, forwarded attachments, references and last-verb metadata. Blind-copy recipients remain in the envelope; Bcc headers are removed before SMTP transmission. Partial SMTP acceptance retries only remaining recipients. |
| 16.x drafts | Add/Change/send, Bcc, body and attachment editing, attachment ClientId-to-FileReference responses, stable attachment IDs after deletion, quota accounting and stable item identity on sending. |
| Calendar | Gregorian daily/weekly/monthly/yearly and ordinal patterns, count/until, implicit recurrence defaults, exceptions, occurrence edits/deletions, all-day boundaries, UTC validation, IANA conversion, 172-byte annual timezone rules, DST gaps/overlaps, structured locations, attendees, categories, reminders, response metadata and calendar attachments. |
| Invitations | iCalendar REQUEST/REPLY/CANCEL/COUNTER/DECLINECOUNTER processing, organizer/attendee ownership checks, sequence checks, organizer updates and removed-attendee cancellations, accept/tentative/decline, per-instance responses, forwarding, 16.1 time proposals and organizer proposal acceptance/decline. Calendar edits and notification outbox entries commit atomically. Declines remove live calendar items while retaining response history. |
| MeetingResponse | Folder/item and Search LongId lookup, optional 16.x SendResponse/body, 16.1 proposed times, recurrence instance responses and CalendarId results. 14.1 clients send their response email separately, as required by that version. |
| Other content classes | Contact, task and note CRUD, class/container/field validation, date and enum validation, duplicate detection, ghosted contact/calendar fields, incomplete-task filtering and attachment restrictions by version. |
| Search / Find / GAL | Mailbox-scoped searches, expression trees, cached result IDs/ranges, 16.1 Find with common KQL mail restrictions, AND/OR/NOT, phrases, prefix wildcards and date/size ranges; directory data comes from enabled visible mailboxes and Central user profiles. |
| ResolveRecipients | Personal contacts and GAL, exact/ambiguous/partial/not-found results, bounded free/busy for internal recipients; unavailable certificates return an explicit certificate status. |
| Provisioning | Temporary/final keys, full acknowledgement required, idempotent acknowledgement retries, policy fingerprints and expiry, per-mailbox overrides, policy enforcement on data commands and pending sync, attachment/body/age limits. Device-side password/hardware restrictions require a successful device acknowledgement. This is not hardware attestation. |
| Account-only wipe | 16.1 pending/delivered/acknowledged states, blocking data access while pending, interruption of long polls and credential revocation after acknowledgement. CoreMX never substitutes a full-device wipe. The server mailbox is retained. |
| Settings / estimates / moves | Device information, user addresses, explicit errors for unsupported settings, filtered estimates, folder/key checks and mailbox-local moves with retry handling. |

## Limits and interoperability work

- Physical Apple Mail/iOS, Samsung Email/Android and Outlook mobile acceptance has not been performed. Validate initial setup, policy acknowledgement, locked-screen push, offline edits, reconnection, large messages, invitation updates, DST changes, draft attachments and account-only wipe on exact OS/app versions before enabling a production endpoint.
- CoreMX is an EAS mail/calendar/contact service, not every Exchange protocol. EWS, MAPI/HTTP, Outlook desktop's native Exchange account mode, public folders, delegated mailbox rights, IRM, S/MIME certificate enrollment/trust/revocation, device-password recovery, out-of-office automation and document-library operations are not implemented.
- Non-Gregorian recurrence arithmetic and iCalendar rules that cannot be represented by EAS are rejected rather than silently converted. Original invitation MIME remains readable. Annual binary timezone rules cannot express every historical IANA rule change; validate imported historic/custom VTIMEZONE data against the actual clients.
- HTML body-part extraction recognizes exact parent-body suffixes and quoted parent text; arbitrary third-party HTML quoting can remain in the returned part. The full body remains available through BodyPreference.
- EmptyFolderContents, persistent conversation moves, recursive folder deletion and some optional protocol extensions return explicit unsupported-operation errors. Conversation IDs are based on Message-ID/References, not subject similarity. Conversation indexes preserve incoming Thread-Index data or build reply ancestry from messages already in the mailbox; missing ancestors cannot be reconstructed from a subject alone.
- Sync sends at most 25 server changes per collection, 128 KiB per email body and 1 MiB per response. Full-item fetches use the 32 MiB transport bound. Search result snapshots are capped at 10,000 IDs. Calendar queries are bounded and recurrence expansion has a work limit.
- Journal/snapshot/response/blob compaction and garbage collection are still needed for large or long-lived deployments. Search scans the selected in-memory mailbox collection; it is not a global scan or a new plaintext KV index. SMTP acceptance followed by a crash still has the usual at-least-once delivery ambiguity.

## Verification

`npm test` exercises encryptedkv storage recovery/isolation, chunk integrity, CentralFW transport, HTTP negotiation/provisioning, WBXML errors, synchronization and retry behavior, smart composition, invitations, DST/recurrence, draft attachments, search, policy/wipe, blind-copy privacy and partial SMTP delivery. `npm run test:browser` exercises the actual Vue page against the actual encrypted mailbox service using synthetic mail; it starts no Node TCP server and sends no internet mail. Production portal generation is checked separately.

Protocol facts were checked against Microsoft's current [MS-ASWBXML publication](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-aswbxml/39973eb1-1e40-4eb5-ac74-42781c5a33bc), [Sync](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-ascmd/89449dc4-678c-4deb-9be2-e1dbbc43e2f5), [packed requests](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-ashttp/9f75a516-edff-48d2-94b9-5f2a3cc570d3), [MeetingResponse](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-ascmd/42ececcd-37df-4340-aa50-783ba714facb), [16.1 time proposals](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-ascmd/85189499-d911-40ae-885d-a55f2cd70c9d), [Find](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-ascmd/2e6a37ac-1b17-421e-85bc-371cbddde930), [AirSyncBase schema](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-asairs/fbbc1af9-5a71-4925-aca8-60a95339c722), and [common status codes](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-ascmd/95cb9d7c-d33d-4b94-9366-d59911c7a060). Calendar parsing and expansion use [ical.js](https://kewisch.github.io/ical.js/api/).
